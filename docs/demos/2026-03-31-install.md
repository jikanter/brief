# brief emit claude --install — Non-destructive CLAUDE.md Integration

*2026-03-31T22:30:08Z by Showboat 0.6.1*
<!-- showboat-id: ad2b5420-2133-49bf-ab19-51e183d8b5d7 -->

The `brief emit claude --install` command injects a briefing into an existing CLAUDE.md without destroying the content already there. It fences the generated section with `<brief:generated>` / `</brief:generated>` markers, so re-running the command updates the briefing in place while leaving everything else untouched. This demo walks through the full lifecycle: first install, update, and coexistence with hand-written content.

## 1. Starting point: an existing CLAUDE.md

Most projects already have a CLAUDE.md with hand-written instructions. We'll set up a realistic scenario with a project that has both an existing CLAUDE.md and a .brief.md.

```bash
mkdir -p /tmp/brief-install-demo && cat > /tmp/brief-install-demo/CLAUDE.md << 'EOF'
# My Awesome Project

This is a web application for managing team documents.

## Build Commands

- Build: `npm run build`
- Test: `npm test`
- Lint: `npm run lint`

## Code Style

- Use TypeScript strict mode
- Prefer functional components with hooks
- All API responses use `zod` for validation
EOF
cat /tmp/brief-install-demo/CLAUDE.md
```

```output

This is a web application for managing team documents.

## Build Commands

- Build: `npm run build`
- Test: `npm test`
- Lint: `npm run lint`
```


## 2. First install

Running `brief emit claude --install` reads the `.brief.md`, emits a CLAUDE.md section, and injects it into the existing file using markers. The hand-written content is preserved.

```bash
cd /tmp/brief-install-demo && brief emit claude --install
```

```output
Installed briefing into CLAUDE.md
```

```bash
cat /tmp/brief-install-demo/CLAUDE.md
```

## 3. Updating the brief

When the brief changes — a new constraint, a validated assumption — re-running `--install` replaces only the fenced section. Content outside the markers is never touched.

```bash
cat > /tmp/brief-install-demo/.brief.md << 'EOF'
---
stack: [TypeScript 5.4, React 18, PostgreSQL 16]
context: [./docs/architecture.md]
---

# Add real-time notifications

## Constraints

### Hard
- Must not degrade page load time by more than 100ms
- All notifications must be delivered within 5 seconds
- WebSocket reconnection must be automatic with exponential backoff

### Soft
- Prefer WebSocket over polling

### Ask First
- Changes to the notification schema

## Sacred
- `src/auth/**` — SOC2 audited authentication module
- `migrations/**` — Historical migrations, never alter

## Assumptions
- [x] WebSocket gateway can handle 5k concurrent connections
- [x] Existing REST API supports event subscriptions

## Deliverable
Working notification system with real-time delivery, read/unread tracking, and browser push notification support.
EOF
echo "Updated .brief.md: added a hard constraint, validated an assumption"
```

## 4. Content added after the brief is also preserved

Users may add hand-written sections below the briefing. The marker replacement is precise — content after the end marker survives re-installs.

```bash

## Team Notes

- Alice owns the WebSocket gateway
- Bob is on-call for database migrations this sprint
EOF
echo "Appended hand-written Team Notes section after the brief markers"
```

## 5. Installing into a new project (no existing CLAUDE.md)

When no CLAUDE.md exists, `--install` creates one from scratch with the markers already in place — ready for future updates.

```bash
mkdir -p /tmp/brief-fresh-demo && cp /tmp/brief-install-demo/.brief.md /tmp/brief-fresh-demo/ && cd /tmp/brief-fresh-demo && ls -a | grep -E "CLAUDE|brief"
```

```output
.brief.md
```

```bash
cd /tmp/brief-fresh-demo && brief emit claude --install && cat CLAUDE.md
```

## 6. Idempotency

Running `--install` multiple times in a row produces the same result. No duplicate markers, no content drift.

```bash
cd /tmp/brief-install-demo && md5 -q CLAUDE.md && brief emit claude --install 2>&1 && md5 -q CLAUDE.md
```

```output
c5a92e757b9c6652619ae913e90e6400
Installed briefing into CLAUDE.md
c5a92e757b9c6652619ae913e90e6400
```

Same checksum before and after — the operation is fully idempotent.

## 7. Switching briefs

A project can swap its active brief entirely — the markers ensure the old briefing is cleanly replaced, not stacked.

```bash
cp tests/fixtures/minimal.brief.md /tmp/brief-install-demo/new.brief.md && cd /tmp/brief-install-demo && brief --file new.brief.md emit claude --install && echo "---" && echo "Marker count: $(grep -c "<brief:generated>" CLAUDE.md)" && echo "---" && cat CLAUDE.md
```


## Summary

`brief emit claude --install` makes CLAUDE.md a live target for structured briefings:

| Scenario | Behavior |
|---|---|
| No CLAUDE.md exists | Creates one with markers |
| CLAUDE.md exists, no markers | Appends fenced section |
| CLAUDE.md has markers | Replaces content between markers |
| Content before/after markers | Preserved on every install |
| Same brief re-installed | Idempotent (byte-identical output) |
| Different brief installed | Old briefing cleanly replaced |

The `.brief.md` remains the source of truth. Run `brief emit claude --install` after editing it, and the CLAUDE.md stays in sync — without a merge, without a copy-paste, without losing anything you wrote by hand.
